# M2: offline parser and local validation

This is a bounded parser for review, not a TeX compiler or a completed M2 submission.
It never executes TeX, downloads source, calls an API, or modifies M1 checkpoints.

## Requirements and boundaries

The table definitions and parsing rules were checked against:

## Run in PowerShell

From this M2 worktree, using Python 3.10+ and dependencies in requirements-m2.txt:

    python -X utf8 -B -m scripts.run_m2 --corpus 'D:\path\to\corpus' --output 'D:\separate-output' --paper 2508.07980 --version v2

Whole corpus:

    python -X utf8 -B -m scripts.run_m2 --corpus 'D:\path\to\corpus' --output 'D:\separate-output'

For a reproducible subset, use --selection path-to-selection.json instead of --paper/--version/--limit-versions. Its working configuration is a JSON list:

    [
      {"arxiv_id": "2508.07980", "version": "v2"},
      {"arxiv_id": "2508.07899", "version": "v1"}
    ]

Exit codes: 0 means every selected version was parsed or confirmed empty; 1 means output was produced but versions require review; 2 means a run-level safety/input/output error. Exit 0 is not a certification of scientific correctness or M2 completion.

The local validation environment used Python 3.14.1 on Windows with the existing pyarrow installation. No dependency was installed globally. For another machine, install requirements-m2.txt in its own environment.

## Input and compilation path

Each paper has metadata.json and manifest.json, with version directories v1, v2, etc.
The runner enumerates versions from manifest, including missing directories; it checks paper/MSSV identity, source file inventory and SHA-256 before parsing.

A root must be the unique uncommented documentclass file. Only explicit input/include paths are followed recursively. Include cycles, paths outside the version directory and symlinks are rejected. Includes in macro definitions and inline verbatim are not executed. Includeonly is supported. Unused auxiliary files do not enter the content.

UTF-8 is used without replacement characters. Latin-1/Windows-1252 require an explicit inputenc declaration; ambiguous encodings fail visibly.

## Processing

- Heading levels follow part/chapter/section/subsection/subsubsection/paragraph/subparagraph without adding nonexistent intermediate headings.
- Sentence leaves protect math, braces, complete citations (including optional prenotes/postnotes with periods), URLs, decimal points and common abbreviations. Itemize/enumerate/description create nested item components.
- Display equations use an equation envelope; align retains an aligned interior. Inline parenthesized math becomes dollar-delimited math.
- Figures/tables are figure leaves containing source-derived semantic content; image binaries are not read or reconstructed.
- A standalone includegraphics command, with an immediately adjacent captionof{figure} when present, is also one figure leaf. The graphic path and caption are retained even when M1 has excluded the image binary. Unknown surrounding commands still fail explicitly.
- Supplement layout supports onecolumn, standard font switches, fontsize, text-preserving makebox, decorative rule lines, and line-break spacing options. makeatletter/makeatother do not change this bounded parser's command tokenizer; arbitrary catcode programming is unsupported. The exact let assignment of thefootnote to relax suppresses its printed marker while keeping footnotetext content. CAS classes additionally retain WriteBookmarks-to-relax as layout metadata. Other let aliases fail explicitly.
- A macro-expanded renewcommand that assigns an exactly empty replacement to thefootnote is likewise marker formatting: footnote text remains intact. Braced/unbraced targets and the standard starred form are accepted. Other targets, parameters or nonempty replacements fail, apart from the explicitly checked English algpseudocode label redefinitions described below. Explicit counter/marker use after such a local change remains blocked because general scoped TeX state is not implemented; the parser never reuses a stale preamble value.
- Optional headings of declared theorem environments and proof are retained as child content, including citations and reference labels. They are semantic text, unlike figure placement or algorithmic line-number options. This prevents a successful parse from silently losing title-only citations.
- Algorithm captions are retained separately. The algorithmic display supports STATE, nested FOR/IF, ELSE, and matching ENDFOR/ENDIF. Both branches are kept in the hierarchy; no pseudocode is executed. Unknown or unbalanced control constructs fail.
- When the actual compilation path declares the cvpr package and no local definition overrides it, the documented CVPR abbreviations etc/ie become etc./i.e. Each affected working version records normalization_notes. Definitions were checked against [the CVPR author-kit source](https://github.com/cvpr-org/author-kit/blob/main/cvpr.sty); the unavailable original style is not executed or claimed verified. This is a limited package convention, not general style-file support.
- References sections/thebibliography are excluded from hierarchy. Acknowledgements, ACM acks and appendices are retained.
- Cleanup removes an explicit formatting set; unsupported commands/environments fail rather than silently deleting unknown content.
- At the start of the document body, author and affil declarations accept an optional star, optional affiliation indices and one balanced argument, including nested names and addresses. These declarations follow the existing author-metadata policy and do not become hierarchy prose. This added syntax is disabled after title rendering or semantic content begins, and inside nested content. Malformed arguments fail explicitly.
- AMS classes (amsart/amsproc/amsbook) retain subjclass codes and the explicit optional edition as a subject-classification component, not discarded prose. Local macro definitions take precedence; malformed/nested declarations remain errors. This convention follows the [AMS class implementation](https://tug.ctan.org/macros/latex/required/amscls/doc/amsclass.pdf).
- Standard sloppypar is transparent paragraph layout: its complete text and list-item boundaries are retained under their semantic parents. A local environment redefinition remains a blocker. The amsmath nobreakdash form keeps literal dashes and an adjacent explicit zero-width hspace; unsupported targets are not dropped. Stroked-L control words preserve the actual Unicode letter and TeX delimiter-space semantics.
- A whole, nonnested math-name macro of the form ifmmode X else $Y$ fi can be expanded in prose using its source-defined text branch Y. Inline/display math is consumed separately before prose macro expansion, so the math branch is not selected or rewritten there. X and Y may differ: the parser never treats the difference as a typo. Arbitrary/nested conditionals remain unsupported. Each affected version records this bounded interpretation in normalization_notes.
- Springer command-form abstract uses the same abstract component and recursive content parsing as the abstract environment. The backmatter phase marker flushes pending text and continues parsing, without inventing a section or truncating the document. A bmhead is represented as an unnumbered section-level heading; acknowledgements and supplementary text remain in the tree, while references follow the existing bibliography separation. An explicit top-level appendices environment starts a root-level appendix component rather than becoming a child of the preceding Declarations section. These bounded conventions match the [official Springer Nature template](https://www.overleaf.com/latex/templates/springer-nature-latex-template/myxmhdsbzkyd); the original class file is not executed. Explicit local definitions of abstract, backmatter and bmhead take precedence, and unknown semantic commands still fail visibly.
- BibTeX entries are read from declared bibliography resources. Cited/nocite entries are retained; manual bibitems are retained even if uncited.
- BibTeX percentages inside values are preserved. String definitions can be shared between declared bibliography files.
- Missing bibliography can fall back to a static `.bbl` only when the compilation path explicitly inputs it, or a bibliography declaration and the unique document root identify its jobname file within the same version. Files from sibling versions/papers or unrelated names are never searched. Existing `.bib`/inline keys take precedence; `.bbl` supplies absent keys. The supported `thebibliography`/`bibitem` form reuses the conservative reader, with explicit REVTeX `bibinfo` fields retained. Unsupported BibLaTeX variants, malformed lists, conditional items and ambiguous associations remain errors. The bounded structured-Biber reader is described below. Working JSON records `bbl_sources`, missing resource requests and bibliography file paths; published schemas are unchanged. The jobname association follows [the LaTeX kernel bibliography implementation](https://github.com/latex3/latex2e/blob/main/base/ltbibl.dtx).
- Bibitems retain raw evidence. Author/title assignment requires explicit newblock boundaries; otherwise these fields stay null. Year/DOI/URL extraction is conservative and is not external verification.
- Reference unification is publication-local: exact DOI or normalized exact title/authors, otherwise identical raw evidence. It chooses a stable first key, unions non-null fields and records conflicting values. Per-version cite aliases are applied before content deduplication.
- Equal cleaned content shares element IDs across versions. Repeated occurrences within one version receive distinct occurrence suffixes, preserving one parent per node. Document roots remain version-specific.

## Additional bounded template support

- IEEEtran keywords are retained as a keywords component; literal two-argument IEEEPARstart keeps the complete first word. Unknown/local environment definitions and undocumented optional arguments remain errors. See [IEEEtran HOWTO](https://tug.ctan.org/macros/latex/contrib/IEEEtran/IEEEtran_HOWTO.pdf).
- Running headers/footers (fancyhead/fancyfoot/fancyhf/markboth/markright) remain raw working `layout_metadata`, separate from scientific prose. Their arguments are balanced and local macro definitions take precedence. Literal assignments to a small set of layout lengths, setspace line spacing and amsmath numberwithin likewise keep evidence instead of executing TeX state. Dynamic values remain errors. See [fancyhdr](https://tug.ctan.org/macros/latex/contrib/fancyhdr/fancyhdr.pdf).
- Centerline and slanted text retain their entire contents; centered graphics can retain an adjacent caption across explicit vertical spacing. No unknown blocks are discarded. Subequations keeps separate formula leaves. Explicit zero-argument source aliases for mathematical begin/end delimiters are expanded before pairing and recorded in normalization_notes; other macros and mismatched delimiters are not repaired.
- ACM CCS XML is validated and retained in working metadata, while ccsdesc text becomes classification content. AASTeX corresponding-author names remain raw metadata; facilities/software backmatter, angle symbols and full deluxetable source (caption/cells/notes/citations) are retained. REVTeX PACS codes are preserved. See [AASTeX facilities/software](https://journals.aas.org/aastexguide/) and [symbol list](https://journals.aas.org/wp-content/uploads/2018/08/aassymbols.pdf).
- Standard textcite/parencite/autocite use the same key collection, alias normalization and protected sentence splitting as cite. Percent-encoded data in the first balanced argument of href/url/path is preserved while ordinary comments remain comments; no URLs are fetched. See [hyperref documentation](https://tug.ctan.org/macros/latex2e/contrib/hyperref/doc/hyperref-doc.html).

Literal citation keys are checked with balanced arguments before bibliography lookup and again after prose macro expansion. Empty, dynamic or nested-brace key forms remain explicit errors; no braces are silently removed to invent a match. Root detection is lexical so malformed unused URL fragments do not become compilation dependencies.

This does not implement arbitrary class files, font rendering, complete algorithm2e/algpseudocode interpreters, general TeX conditionals or general automatic root selection. New successes require source comparison; parsed syntax alone is not a certification of full M2 correctness.


## Further source-verified syntax (cohort 151)

- Literal iftrue/iffalse branches are selected before includes and citation collection. Nested primitive boundaries are balanced; declarations inside those branches and unknown predicates remain explicit errors. Inactive inputs/references are not collected. The selected interpretation is recorded in normalization_notes.
- Source-defined newenvironment bodies and their balanced arguments are expanded with recursion limits. Unknown commands in either boundary still fail. Renewed/pre-existing environments retain the conservative guard. Source-written theorem declaration factories are restricted to literal declaration commands; body newtheorem declarations retain their labels in working metadata.
- Algorithmic/algpseudocode additionally support State/Require/Ensure, Function/Procedure, ForAll/While, ElsIf and their balanced ends. Call, Return and Comment are interpreted only in pseudocode scope. Control-line comments are retained. Algorithm2e supports bounded brace-body For/While/If/lIf/Else forms, input/output/result/return and literal SetKwInOut definitions; indentation controls remain layout evidence. No branch is executed and unknown forms are not skipped.
- Frontmatter, titlepage, typography-size containers, minipage, raisebox/framebox/fbox and REVTeX widetext retain all body text. Explicit template declarations, diagnostics and literal glue remain working layout_metadata. AAAI links retain labels and URLs. Fontawesome/pifont symbols retain exact source tokens instead of guessed glyph mappings. IEEE biographies require the actual mandatory author argument; missing pictures do not erase biography text.
- Tcolorbox supports a text title plus an explicit presentation-key subset. Titles become content under the box component. Hooks, overlays, unknown keys and executable options fail instead of disappearing. Source-defined example wrappers therefore keep their title and content as separate structural children.
- Verbatim/verbatim* become literal leaves with exact whitespace, percent signs and commands preserved. Includes/citations/comments inside them do not execute or become references; code is excluded from root and bibliography structural searches. Their content is intentionally not prose-normalized because indentation can change program meaning. A source today token stays unresolved, with a normalization note, rather than becoming a fabricated compilation date.
- Removing formatting groups and expanding prose macros preserves control-word token boundaries (for example textbf{...quad}Table must not create a new quadTable command). Literal jot/bibsep spacing, algorithm control-line breaks and NoHyper wrappers keep all content. Mathtools is recognized as providing the amsmath text command. Empty changes replacement markers preserve the following text; nonempty replacements still require an explicit draft/final interpretation.
- Inline bibliography URL-style guards reuse bounded .bbl validation; conditional items/resources remain errors. BibTeX field identifiers may start with an underscore (for example JabRef's __markedentry), with raw evidence retained. Conflicting duplicate fields, missing keys and ambiguous citation identity remain blockers.

These rules are source-derived subsets, not a claim to compile every package or recover missing dependencies. Publication-local bibliography union can add fields/rows when another version starts parsing. Compare per-version content and aliases as well as the whole-paper union when reviewing reruns.

## Output and schemas

Each invocation selects an immutable run directory from input, selection and parser fingerprints:

    run-<fingerprint>/
      definition.json
      papers/<paper-key>/result.json
      data/elements/part-00000.parquet
      data/hierarchy/part-00000.parquet
      data/bibtex/part-00000.parquet
      output_checksums.json
      attempts/<attempt-id>.json

Only the following columns are in the published-format tables:

| Table | Columns |
| --- | --- |
| elements | element_id:string non-null; arxiv_id:string non-null; kind:dictionary(string); content:string |
| hierarchy | arxiv_id:string non-null; version:int; element_id:string non-null; parent_id:string non-null |
| bibtex | arxiv_id:string non-null; citation_key:string non-null; entry_type:dictionary(string); title:string nullable; authors:list[string] nullable; year:int nullable; doi:string nullable; journal:string nullable; url:string nullable |

Working JSON retains version statuses, ownership, included files, raw bibliography evidence, aliases and conflicts separately. M3 can join bibtex and M1 references by arxiv_id; this task does not implement matching or change M1 tables.

Statuses:

- success: the supported parser path and table checks completed; missing bibliography is recorded separately if the text contains no citations/declarations.
- empty_no_tex: M1 explicitly confirmed no TeX; no elements or edges are invented.
- source_unavailable: M1 download failed/pending/rate-limited; not treated as empty.
- input_error: source/checksum evidence is missing or inconsistent.
- parse_error: missing compilation resource, missing cited bibliography entry, ambiguous source or unsupported syntax; this version contributes no official rows, while other valid versions remain.

Rerun reads verified cached paper results and compares Parquet rows/schema/checksums. It does not append duplicate rows or silently repair corrupted output. Changed source/parser/selection creates another run directory. A stale writer lock requires manual review; do not delete it while a writer is active.

## Measurement and limitations

Each attempt records elapsed perf_counter wall time for input reading/fingerprinting, parsing, validation and writing/rereading Parquet. Cached attempts are explicitly separate. This is a local sample measurement, not the required final Colab CPU benchmark. RAM sampling and the report Book are not implemented here.

Not supported: general TeX conditionals, dynamic import/subfile compilation, parameterized TeX primitive macros, arbitrary package-defined prose commands/environments, full biblatex filters, TeX-escaped code-block interpretation and recovery of absent bib/bbl/sty resources. Unknown encodings are not guessed. Unknown syntax cannot be converted into a success by dropping it.

Missing compilation dependencies remain parse_error, not empty_no_tex. A missing image referenced by includegraphics is expected under the M1 extraction policy and does not prevent a figure leaf. A missing input file ending in bbl or tikz is different: it can contain bibliography or drawn text, so its content is not guessed even though M1 did not retain that extension. Missing tex/bib files likewise remain explicit, and another version's files are never substituted. The runner separately retains M1-confirmed no-TeX and unavailable-source records.

Conservative bibliographic matching may leave duplicates whose identity cannot be established. Bibitem metadata can remain incomplete. These are visible limitations for review before M3.

## Independent supplementary documents and root selection

When several documentclass candidates exist, the parser chooses a root only if
exactly one candidate remains after identifying explicit supplementary documents.
Evidence is an explicit Supplemental Material/Supplementary Information title or
heading (including an opening display title), or manuscript=suppinfo class option.
Comments, literal blocks, ordinary prose and filenames do not establish a role.
Uncertain declarations or multiple remaining main candidates retain the root error.
The working version record stores root_selection and excluded supplement evidence,
including when later parsing fails. Independent supplements are excluded by this
policy; this does not claim their contents were parsed. All active input/include
files and appendices of the selected main path still follow the existing gathering
rules. Published table schemas and the M1 corpus are unchanged.

## Bounded prose commands from the nine-cohort scan

- Standard normalfont is a font declaration, so the following group and its text,
  math and citations remain in the stream. Flushbottom and REVTeX onecolumngrid
  are layout controls, retained in working layout_metadata. Local definitions win.
- Definecolor reads its balanced optional type and three mandatory arguments.
  Literal rgb/RGB/gray/cmyk and named specifications are supported; executable,
  unknown, incomplete or out-of-range definitions fail explicitly. Color declarations
  stay in layout_metadata; they do not consume the following scientific text.
- REVTeX altaffiliation reads its optional prefix and balanced address only before
  top-level content/title rendering, retaining both as working metadata. IEEEtran
  IEEEpeerreviewmaketitle uses the existing repeated-title metadata policy.
- Explicit AMS/amsthm qed markers remain in content. A source-defined qedsymbol
  follows normal macro validation so custom words/formulas are not discarded.
- REVTeX onlinecite participates in citation-key validation, bibliography selection,
  sentence protection and publication-local alias rewriting, including optional notes.
  The onlinecite spelling is retained; no citation numbers are invented.
- Hyperref label/text and URL/category/name/text forms retain destination evidence
  in layout_metadata and recursively parse the displayed text, including nested
  math, citations and ref* (with hyperref). Missing/dynamic labels or unsupported
  displayed commands remain errors rather than being hidden inside a link.
- CVPR maketitlesupplementary creates a root-level Supplementary Material heading
  and continues along the existing compilation path, including appendices. Its
  repeated paper title follows the existing title-metadata policy. A normalization
  note states that this is a bounded template convention, not execution or
  verification of the unavailable original style. Unknown/local definitions do not
  use this fallback. Independent supplements still follow the separate root policy.

  layout validator. Unexplained prose, dynamic lengths and other commands still
  fail; the prefix is never deleted without validation.
- Keywords from interact, l4dc2025 and spconf retain a keywords component, math,
  citations and following content. Unsupported options remain errors.
- The exact JHEP begingroup/raggedright/thebibliography/endgroup wrapper is

- Static .bbl setup supports source-verified identity, URL and hyperlink fallback

  Conditions are not executed: item membership cannot depend on them. Raw item

  branches, structural redefinitions and conditional items still fail.
- Lstlisting with the listings package supports literal code and a bounded set of

  local override, retain their balanced arguments and original number/unit

  moderncv letters with makelettertitle, and explicit Summary of Changes author

  sharing the balanced/group and BibTeX field/entry normalizers. It supports one

  unexported producer metadata stay in working evidence; original files are not
  changed. Unknown structural macros, ambiguous identities, malformed counts
  and nonglobal refsections remain errors. Heading-only printbibliography

  converted files; converted_and_removed inputs require an explicit, verified

Published elements/hierarchy/bibtex columns and M1 source/checkpoint bytes remain
unchanged. These checks do not replace a fresh full scan of the 125 cohorts.
