# M3 — reference matching

M3 matches the BibTeX entries M2 extracted against the arXiv-keyed references M1 crawled,
for one publication at a time. The statement frames it as an `m x n` binary matrix: `m`
entries, `n` references, one "yes" cell per labelled row, or an all-no row when the cited
work is not among that publication's references.

Two deliverables sit on top of the matrix: a **manual pool** of human-labelled rows
(ground truth) and an **automatic pool** at least 10% the size of what remains, labelled
by a classic matcher (regex/string similarity, not a trained model). A supervised ranker
is then trained on those labels and scored with MRR@5.

## Quota

The statement's quantities scale with the number of members `k`. For this group `k = 4`:

| Requirement | Formula | Value |
|---|---|---|
| Manually labelled publications | `5k` | **20** |
| Labelled entries | `100k` | **400** (floor), 469 selected |
| Entries per publication | `>= 20` | 20–30 selected |
| Automatically matched publications | `>= 10%` of the rest, `>= 2k` | **245** (of 2 443) |
| Test set | `k` manual + `k` automatic | 4 + 4 |
| Validation set | `k` manual + `k` automatic | 4 + 4 |
| Training set | the remainder | 12 manual + ~237 automatic |

So each member labels **5 publications, ~115 entries** — 469 rows for the group, a little
above the 400 floor so a few entries can be dropped if one turns out unlabelable.

## Inputs

Both tables already exist; no corpus or LaTeX work is involved.

- `references.parquet` — M1's normalized references, 96 641 rows over 4 382 publications,
  100% `ref_arxiv_id` coverage.
- `bibtex` shards — M2's entries, 133 115 rows over 2 748 publications.

They join on `arxiv_id`: 2 463 publications appear in both, giving 3 860 241 candidate
cells. Only 78.6% of M2 entries carry a title and 79.8% carry authors, so the shortlist is
drawn from publications where at least 20 entries carry both.

## Choosing the 20 publications

`select_labeling_publications` filters on the material a labeller actually reads and then
ranks by labelling cost (`labelable_entries * references`). Cost mattering is obvious;
the reference floor matters because every reference is a potential training positive, so
a publication with 30 entries and 8 references would cost 30 decisions and teach the
ranker almost nothing.

| Minimum references | Entries | References (positives) | Cells | Per member |
|---|---|---|---|---|
| 8 | 434 | 181 | 4 016 | 108 |
| 12 | 446 | 251 | 5 662 | 112 |
| **15** | **469** | **315** | **7 369** | **117** |
| 20 | 525 | 422 | 11 201 | 131 |

`minimum_references=15` is the setting used: it nearly doubles the positives over the
cheapest setting for 8 more decisions per member.

## Labelling protocol

One decision per entry, recorded with the reviewer and a timestamp:

- the reference that is the same work, or
- **none**, when the cited work is not among the publication's crawled references.

A journal or conference version matched to its arXiv preprint counts as the same work
(the statement is explicit about this). Entries carrying neither title nor authors are
left out of the pool rather than guessed at — they stay unlabelled downstream.

## The labelling page

`src/m3/review.py` builds the payload, `src/m3/labelling_page.html` is the page, and the
page is a single self-contained file — no server, no build step, no network:

```bash
python scripts/build_labeling_page.py \
  --bibtex  <run>/data/bibtex \
  --references references.parquet \
  --members 4 --names "ana,bo,cy,dee" \
  --out labelling/m3-labelling.html
```

Omit `--shortlist` and the 20 publications are derived from the quota; pass it to pin a
specific set. The page shows, per entry: the citation key, type, title, authors, year,
venue and DOI, and beside it every crawled reference of that publication with its title,
arXiv id, authors and date. Title tokens shared with the entry are highlighted, so a
glance separates the plausible from the irrelevant.

Each row arrives with a **draft suggestion** and the evidence behind it — title
similarity, how many surnames are shared, and the year comparison — plus a confidence
tier. The draft is computed from the cell features with fixed weights (`SCORE_WEIGHTS`),
never from the model that is later scored against these labels. Rows are ordered easy to
hard, so the unambiguous half is a few keystrokes each and attention lands on the
remainder. A near-identical title whose number differs ("… Part I" against "… Part II")
is explicitly downgraded: a title score cannot tell those apart.

Keys: `j`/`k` move, `1`–`9` pick, `Enter` confirm, `n` none, `s` skip, `b` back, `u` undo,
`e` export. Progress lives in the browser's local storage, and every sitting should end
with **Export labels** — the exported file is the only thing that counts.

The exported rows carry `arxiv_id`, `citation_key`, `groundtruth_arxiv_id` (null for a
none row), `decision`, `reviewer` and `reviewed_at`. Rows nobody accepted or corrected
are never written: a draft the labeller skipped is discarded with the page.

## Merging the four exports

```bash
python scripts/merge_m3_labels.py exports/*.json --out labels.jsonl --members 4
```

Exports are keyed by `(arxiv_id, citation_key)` and merged newest-first, so a corrected
re-export wins. `review.validate_labels` then checks the quota before anything is written
and refuses a set with unsigned rows, duplicate labels, publications below 20 entries, or
fewer than `100k` rows. `--allow-partial` writes the merge anyway for an interim look.

## Measurements

On the selected 20 publications:

- 469 labelable entries, 315 references, 7 369 candidate cells.
- 303 rows (65%) arrive with a high-confidence draft, 16 medium, 150 with no convincing
  candidate — consistent with M1's reference recall: a publication's 15–30 crawled
  references cover only part of a bibliography of 20–60 cited works.
- Of the 319 drafts that name a candidate, 300 (94%) share at least one author surname
  with the entry.

## Limitations

- M1's reference table has no DOI column, so DOI can never confirm a match here; the
  `doi_exact` cell feature is a constant 0 and is dropped from the model's inputs.
- An entry whose title and authors are both missing cannot be labelled; across the
  joined corpus that is 22.6% of entries, and the shortlist avoids those publications.
- Test and validation each take one automatically matched publication per member, so part
  of the reported MRR@5 is measured against silver labels. Report the manual-pool and
  auto-pool test scores separately.
